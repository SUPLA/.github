# Support

Use the right support channel for the type of problem.

## Where to ask for help

### 1. Usage, configuration, and self-hosting questions

Use the community forum:

- https://forum.supla.org/

Good examples:
- installation questions
- configuration help
- migration questions
- "how do I..." usage questions
- self-hosting and operational troubleshooting

### 2. Project overview and repository routing

Start here:

- organization profile: [`profile/README.md`](profile/README.md)
- repository index: [`docs/repositories.md`](docs/repositories.md)
- architecture overview: [`docs/architecture.md`](docs/architecture.md)

### 3. Actionable repository bugs and feature requests

Use GitHub Issues in the **correct repository** when you can provide enough detail to reproduce or scope the work.

Before opening an issue:
- confirm the correct target repository,
- search for existing issues,
- include logs, steps, environment details, and expected behavior.

### 4. Security vulnerabilities

Do **not** use public issues.

Follow [`SECURITY.md`](SECURITY.md).

## What not to use GitHub Issues for

Please avoid opening GitHub issues for:

- general support requests,
- account-specific questions,
- forum-style discussion,
- vague reports without reproduction details,
- security disclosures.

## What to include when you ask for help

The more concrete your report, the better.

Include when relevant:
- repository name,
- branch / release / tag,
- operating system,
- device or hardware model,
- deployment method,
- exact steps,
- logs and screenshots,
- expected result,
- actual result.
